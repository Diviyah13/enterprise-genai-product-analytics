# Metric Dictionary

This document defines the core product analytics metrics used in the Enterprise GenAI Product Analytics project.

The purpose of the metric dictionary is to ensure that each KPI has a clear and reproducible business definition before it is reported.

## Core Metrics

| Metric | Definition | Calculation | Business Purpose |
|---|---|---|---|
| Questions Asked | Total number of distinct valid user questions submitted during the reporting period. | `COUNT(DISTINCT message_id)` | Measures overall AI assistant usage volume. |
| Unique Users | Number of distinct external users who submitted at least one valid question. | `COUNT(DISTINCT user_id)` | Measures breadth of user adoption. |
| Active Organisations | Number of distinct valid organisations with at least one valid AI interaction. | `COUNT(DISTINCT organisation_id)` | Measures client-level adoption of the AI assistant. |
| Threads | Number of distinct valid conversation threads. | `COUNT(DISTINCT thread_id)` | Measures the number of AI conversations initiated. |
| Multi-turn Threads | Conversation threads containing more than one valid user question. | `question_count > 1` | Measures conversations where users continue interacting beyond the first question. |
| Multi-turn Rate | Percentage of valid conversation threads containing more than one user question. | `Multi-turn Threads / Total Threads × 100` | Provides a proxy for deeper conversational engagement. |
| Questions per Organisation | Average number of questions generated by each active organisation. | `Questions Asked / Active Organisations` | Measures usage depth at client level. |
| Questions per User | Average number of questions generated by each active user. | `Questions Asked / Unique Users` | Measures usage depth at user level. |
| MoM Question Growth | Percentage change in questions asked compared with the previous reporting month. | `(Current Month Questions - Previous Month Questions) / Previous Month Questions × 100` | Shows whether AI usage is growing or declining month over month. |

---

## Valid Interaction Population

A valid interaction must meet all of the following criteria:

- The event represents a user-submitted question.
- The organisation is not classified as a test organisation.
- The organisation is not classified as a demo organisation.
- The user is not classified as an internal employee.
- The message is unique after deduplication by `message_id`.

These rules ensure that product KPIs reflect genuine external client activity rather than system events, testing activity, demonstrations, internal usage or duplicated records.

---

## Metric Design Principle

Raw event data does not automatically represent a business KPI.

For example, AI adoption could potentially be measured using:

- registered users
- users who logged in
- users who submitted at least one question
- organisations with at least one question
- organisations that return repeatedly
- users who engage in multi-turn conversations

For this project, metric definitions are documented before aggregation so that each reported KPI has a consistent business meaning.

---

## Analytical Principle

Different metrics require different aggregation keys:

| Metric Type | Source of Truth |
|---|---|
| Question volume | `message_id` |
| User adoption | `user_id` |
| Organisation adoption | `organisation_id` |
| Conversation engagement | `thread_id` |
| Time trend | reporting month |
| Client comparison | segment |

This helps prevent technically valid but business-invalid counts.
